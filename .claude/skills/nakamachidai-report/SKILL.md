# 仲町台店 週次レポート作成スキル

オーナーズコンパスの顧客「仲町台店」（コンビニ）について、毎週月曜13:00〜17:00に勤務する
当方スタッフ・小泉Mから上がってくる週次レポート（箇条書き）を、見やすくビジュアル化した
**報告書＋提案書**の Word ファイルに仕上げる。

## 背景・前提
- 店舗：仲町台店（横浜・仲町台。FamilyMart系コンビニ）。オーナーは鈴木オーナー。
- 当方担当：小泉M（毎週月曜13〜17時、コンサルティング勤務）。
- 過去の関連資料：リポジトリ直下の `make_doc.py` / `仲町台店_コンサル提案書.docx`（売場改善の初期提案）。
- 関連店舗：獅子ヶ谷店（弁当を絞りチルド弁当・調理麺を伸ばした成功店。横展開の参照先）。
- 業界用語：フェイスアップ＝前出し、見切り／値引き＝値下げ、プライチ＝レジ前1品プロモ、
  プラスワン＝ついで買い提案、デイリー＝チル弁・麺類・サラダ・惣菜、SKU＝品目数、
  H/C＝米飯横の什器（ホットケース）。

## 手順

1. **生のレポートを読み解く。** 小泉Mのレポートは概ね次の見出しで届く（表現は揺れる）：
   - 売場でやったこと → `done`
   - お店にいて感じたこと（課題） → `issues`
   - オーナーに提案したこと → `proposed`
   - 来週やること（当方） → `next_us`
   - 来週までにやってもらうこと（店舗） → `next_store`

2. **構造化データ(JSON)を作る。** 下記スキーマで `reports/仲町台店/<訪問日 YYYY-MM-DD>.json` を書く。
   - 報告パート（`done` / `issues` / `proposed` / `next_us` / `next_store`）は**レポート原文に忠実に**。
     原文にない事実を作らない。表現の整理・敬体への統一・要約は可。
   - 提案パート（`summary` / `recommendations` / `roadmap` / `kpi` / `footer`）は、当方コンサルとしての
     **付加価値（良しなにまとめた提案）**。「課題→原因→対策」で具体化する。これは当方の見立てであることが
     伝わる粒度で書く（断定的な数値の捏造はしない。基準値・目標値は「◯」等のプレースホルダで残す）。
   - `report_no` は前回までのファイルを見て連番。初回は1。
   - 過去回がある場合は `reports/仲町台店/` の既存JSONを確認し、継続課題（前回からの宿題）を踏まえて書く。

3. **生成する。**
   ```bash
   python .claude/skills/nakamachidai-report/build_report.py \
     "reports/仲町台店/<YYYY-MM-DD>.json" \
     "reports/仲町台店/仲町台店_週次レポート_第<N>回_<YYYYMMDD>.docx"
   ```

4. **検証する。** python-docx で開き直し、tables/paragraphs が取れること・例外が出ないことを確認する。
   （この環境では LibreOffice が壊れており PDF プレビューは作れない。フォントは Yu Gothic 前提。）

5. **コミットして push。** ブランチ `claude/nakamachi-store-consultation-Helmz`。JSON と .docx の両方を含める。
   PR が無ければドラフトで作成。コミットメッセージ末尾に必須フッターを付ける。

6. **報告する。** 生成した .docx を `SendUserFile` でユーザーに渡し、当方提案として付け足した点を簡潔に伝える。

## JSON スキーマ

```jsonc
{
  "store": "仲町台店",
  "client": "オーナーズコンパス",
  "report_no": 1,                 // 連番
  "visit_date": "2026年6月8日(月)",
  "consultant": "小泉M",
  "schedule": "毎週月曜 13:00〜17:00",
  "summary": "本日の総括（当方視点）",
  "done":     [{"title":"", "detail":"", "status":"完了|継続（来週）"}],
  "issues":   [{"observation":"気づき・現状", "action":"対応の方向性"}],
  "proposed": ["オーナーと合意・提案した事項", "..."],
  "next_us":    ["当方が翌週やること", "..."],
  "next_store": ["店舗にお願いすること", "..."],
  "recommendations": [               // 当方の重点改善提案（付加価値）
    {"theme":"", "issue":"課題", "cause":"原因", "measure":["対策1","対策2"]}  // measure は文字列でも配列でも可
  ],
  "roadmap": ["STEP1\n短い\n見出し", "STEP2\n...", "..."],  // 2〜6個。\n で改行
  "kpi": [["項目","指標(KPI)","現状","目標"], ...],
  "footer": "運用のポイント"
}
```

## 生成物のレイアウト
- ネイビーのタイトルバナー＋情報バー（回数／訪問日／担当／勤務）
- サマリーボックス
- **報告パート**：1.実施作業（表＋ステータス色分け）／2.現状と気づき（課題→対応の2列表）／3.オーナー合意事項（チェックボックス箇条書き）
- **提案パート**：4.翌週アクション（当方／店舗の2列）／5.重点課題と改善提案（課題=赤・原因=灰・対策=緑のカード）／6.優先順位ロードマップ（矢印図）／7.KPI管理表
- フッター：運用のポイント

## メモ
- 配色・部品の実装は `build_report.py`。レイアウトを変えたいときはこのスクリプトを編集する。
- レポートが画像（写真）で来る場合は、まず文字起こししてからスキーマに落とす。

# オーナーズコンパス 店舗 週次レポート作成スキル（v2）

オーナーズコンパスが顧客店舗（コンビニ）に毎週訪問するコンサル担当（小泉M 等）から
上がってくる週次レポート（箇条書き）を、見やすくビジュアル化した**報告書＋提案書**の
Word ファイルに仕上げる。複数店舗・週次の進捗トラッキングに対応。

## 背景・前提
- 顧客例：**仲町台店**（横浜・仲町台。FamilyMart系。鈴木オーナー。担当・小泉M、毎週月曜13〜17時）。
- 参照店：**獅子ヶ谷店**（弁当を絞りチルド弁当・調理麺を伸ばした成功店。横展開の参照先）。
- 過去資料：リポジトリ直下 `make_doc.py` / `仲町台店_コンサル提案書.docx`（初期の売場改善提案）。
- 業界用語：フェイスアップ＝前出し、見切り／値引き＝値下げ、プライチ＝レジ前1品プロモ、
  プラスワン＝ついで買い提案、デイリー＝チル弁・麺類・サラダ・惣菜、SKU＝品目数、
  H/C＝米飯横の什器（ホットケース）。

## トリガー
- 「**<店舗名>レポートよろしく**」「<店舗名>のレポートまとめて」＋生レポート → 週次レポート1枚を生成。
- 「**店舗横断サマリー**」「全店まとめて」 → `build_summary.py` で全店一覧を生成。

## 手順（単店の週次レポート）

1. **生レポートを読み解く。** 担当の箇条書きは概ね次の見出しで届く（表現は揺れる）：
   売場でやったこと→`done` ／ 感じたこと（課題）→`issues` ／ オーナーに提案→`proposed` ／
   来週やること（当方）→`next_us` ／ 来週までにやってもらうこと（店舗）→`next_store`。
   画像で来たらまず文字起こしする。

2. **過去回を確認する。** `reports/<店舗名>/` の既存 JSON を見て `report_no`（連番）を決める。
   前回がある場合は、前回の `next_us`/`next_store` の進捗を `followups` に、
   未解決の課題を `carryover` に書く（ジェネレーターが「前回アクションの振り返り」「継続課題」
   「KPI 前回比」を自動表示する。`followups` 未記入なら前回アクションを"確認中"で自動列挙）。

3. **構造化データ(JSON)を作る。** 下記スキーマで `reports/<店舗名>/<訪問日 YYYY-MM-DD>.json` を書く。
   - 報告パート（`done`/`issues`/`proposed`/`next_us`/`next_store`/`followups`）は**原文に忠実に**。
     原文にない事実を作らない。表現整理・敬体統一・要約は可。
   - 提案パート（`summary`/`recommendations`/`roadmap`/`kpi`/`carryover`/`footer`）は当方コンサルの
     **付加価値**。「課題→原因→対策」で具体化。数値の捏造はしない（不明な現状値は空欄／プレースホルダ）。
   - **KPI に実数を入れると達成度ゲージ（棒グラフ風）が自動描画される**。`現状` と `目標` の
     両方が数値（"12日" "640円" 等でも可）の行のみゲージ化される。

4. **生成する。**
   ```bash
   python .claude/skills/oc-store-report/build_report.py \
     "reports/<店舗名>/<YYYY-MM-DD>.json" \
     "reports/<店舗名>/<店舗名>_週次レポート_第<N>回_<YYYYMMDD>.docx"
   ```
   （前回比は同フォルダの過去回 JSON から自動取得される。）

5. **検証する。** python-docx で開き直し、例外なく tables/paragraphs が取れることを確認。
   （この環境では LibreOffice が壊れており PDF プレビュー不可。フォントは Yu Gothic 前提。）

6. **コミットして push。** ブランチ `claude/nakamachi-store-consultation-Helmz`。JSON と .docx 両方を含める。
   PR が無ければドラフトで作成。コミットメッセージ末尾に必須フッターを付ける。

7. **報告する。** 生成した .docx を `SendUserFile` で渡し、当方提案として付け足した点を簡潔に伝える。

## 手順（店舗横断サマリー）
```bash
python .claude/skills/oc-store-report/build_summary.py reports "reports/_店舗横断サマリー.docx"
```
各店舗フォルダの**最新回**を集約し、店舗ごとの重点課題・翌週アクション・総括を1枚にまとめる。

## JSON スキーマ
```jsonc
{
  "store": "仲町台店",
  "client": "オーナーズコンパス",
  "report_no": 1,                       // 連番（前回比・サマリーの判定に使用）
  "visit_date": "2026年6月8日(月)",
  "created": "2026年6月9日",            // 任意。無ければ visit_date
  "consultant": "小泉M",
  "schedule": "毎週月曜 13:00〜17:00",
  "summary": "本日の総括（当方視点）",
  "followups": [                         // 第2回以降。前回アクションの進捗（任意・自動補完あり）
    {"owner":"当方|店舗", "item":"前回のアクション", "status":"完了|進行中|未着手", "note":"補足"}
  ],
  "carryover": ["継続課題（前回から持ち越し）"],   // 第2回以降・任意
  "done":     [{"title":"", "detail":"", "status":"完了|継続（来週）"}],
  "issues":   [{"observation":"気づき・現状", "action":"対応の方向性"}],
  "proposed": ["オーナーと合意・提案した事項"],
  "next_us":    ["当方が翌週やること"],
  "next_store": ["店舗にお願いすること"],
  "recommendations": [                   // 当方の重点改善提案（付加価値）
    {"theme":"", "issue":"課題", "cause":"原因", "measure":["対策1","対策2"]}  // measure は文字列でも可
  ],
  "roadmap": ["STEP1\n短い\n見出し", "STEP2\n..."],   // 2〜6個。\n で改行
  "kpi": [["項目","指標(KPI)","現状","目標"]],          // 現状・目標が数値なら達成度ゲージを自動描画
  "footer": "運用のポイント"
}
```

## 生成物のレイアウト（v2）
- **表紙ページ**（店舗名・回数・訪問日・担当・作成日＋目次）→ 改ページ
- ネイビーのタイトルバナー＋サマリーボックス
- **報告パート**：（前回がある場合）前回アクションの振り返り・継続課題／実施作業（表＋ステータス色分け）／
  現状と気づき（課題→対応の2列）／オーナー合意事項
- **提案パート**：翌週アクション（当方／店舗）／重点課題（課題=赤・原因=灰・対策=緑のカード）／
  優先順位ロードマップ（矢印図）／KPI管理表（前回比つき）＋数値目標の達成度ゲージ
- フッターに**ページ番号**、巻末に「運用のポイント」

## メモ
- 配色・部品・レイアウトの実装は `build_report.py`。横断サマリーは `build_summary.py`。
- 外部チャートライブラリは使わず、ゲージは塗り分けセルで描画（環境依存なし）。
